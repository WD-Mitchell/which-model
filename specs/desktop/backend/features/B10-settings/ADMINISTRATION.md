# Desktop administration correction (#347)

Requester decision: expose the company stack through the desktop before merge/release. This supersedes CLI-only administration and source-only macOS distribution limitations; protected policy remains read-only.

The new EngineHost.administration / AdministrationAPI facet reuses company.Snapshot, credential.MigrationReport and privacy.Summary. Status returns independently loaded policy, effective native-store preference and the latest in-memory maintenance result. It performs no credential lookup. Invalid required policy produces an actionable error. VerifyDelegation rechecks each protected CodexBar image/config without running it and reports per-pair results; this is point-in-time evidence, never approval or a replacement for use-time checks.

SetNativeStore(enabled) is personal-only, persists auth.native_keychain and enables auth.use_keychain when selecting native storage. All settings mutations preserve the preference. Managed storage is administrator-controlled. Migrate(provider, removeSource, replace) reuses the existing verified migration and independent authority checks. A personal transition updates the live desktop config and disk after secure verification, before optional removal. Completed/partial operations return MigrationReport plus optional fixed error text; failures never discard secure-store/legacy-copy/recovery evidence. Only declared provider IDs and artificial-analysis are accepted.

Maintain(operation, categories, projectRoot, confirmed) accepts cleanup or purge and the canonical privacy categories. Purge requires explicit confirmation and at least one selected category. Cleanup follows managed retention; personal cleanup reports inactive retention. Personal explicit purge remains available. An optional absolute project root selects only the two owned legacy audit files. No arbitrary file or command is accepted. Reports retain per-category success/failure counts and a UTC timestamp. Automatic maintenance stores its last report too. Usage purge serializes with collection and clears in-memory evidence; later enabled collection can create new records. Files owned by providers, credentials, config and catalogs remain outside this workflow.

Settings adds Security & privacy: policy identity, allowed providers/sources, retention, integration/custom execution/migration restrictions, approved executable/CodexBar paths and hashes; native storage selection; explicit migration and cleanup/purge confirmation. Sensitive values never enter the UI. Partial outcomes stay visible until the next operation. The UI does not enable policy-restricted options or claim an approval entry has passed verification without an explicit check.

Managed harness DTOs identify administrator-controlled commands and show the protected path/argument template. Unapproved commands are unavailable, never replaced by mutable commands. The preview is a template, not proof of successful execution or verification. Personal previews remain unchanged.

Pinned tests: managed command divergence; status without credential access; managed native-setting refusal; verified migration with partial removal; personal preference transition; selected purge and missing confirmation; partial maintenance results; UI confirmation and error-report persistence; personal preview compatibility.

Offline distribution integration requires the Wails asset-discovery index to contain the offline entry, never the full app entry. Offline API calls use generated package-qualified bindings. Pinned checks cover the isolated asset closure including index.html and startup/profile changes through those bindings.
