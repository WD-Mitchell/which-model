# F12 — Credentials: resolvers, chain, OAuth device flow

## Purpose

F12 turns a provider's declarative `usage.AuthSource` chain (F11) into one validated `usage.Credential`, implementing every credential-loading semantic the research spec pins down: bounded reads, opaque-token shape checks, permission warnings without remediation, CLI shell-out that degrades to "no candidate", keychain retrieval, the generic OAuth device-code state machine Copilot uses, and the lifecycle store for credentials created by which-model. It provides both `ResolveChain` for provider-native sources and `ResolveProvider` for the same ordered chain plus managed device-flow credentials.

All resolvers operate only behind the §1a gates (binary built without `nousage`, usage enabled, provider explicitly enabled) — the gates themselves are enforced by F21/F24 before any F12 code is reachable (annex-a §1a).

## Behaviour

1. **Resolver contract.** `Resolver` is `Resolve(ctx) (usage.Credential, error)`. The sentinel `ErrNotFound` means "no candidate from this source — continue the chain"; any other error is a hard, Failure-coded error that aborts the chain (`usage.NewFailureError`). A resolver NEVER returns a partially-populated Credential together with an error.
2. **EnvResolver.** Reads `Var` (then `Extra` names) from the environment. Missing, empty-after-trim, or a value failing `security.ValidateOpaqueToken` → `ErrNotFound` (candidate unavailable; `docs/plan/research/usage-allowance-checks-spec.md` §2.1/§2.2 env-override posture). Values are trimmed and, when the first and last characters are a matching quote pair (`"`/`"` or `'`/`'`), unquoted (CodexBar `cleaned()`, annex-a §4). Success → `Credential{Token, Extra, Source: AuthEnvVar}`.
3. **FileResolver.** Reads each `Paths` entry with `security.ReadBoundedFile(path, security.MaxCredentialBytes)` (F05; mirrors prototype `readBoundedFile` 1 MiB cap, `usage-allowance-checks-spec.md` §1). Nonexistent path → `ErrNotFound` (next path). Existing file that fails read/stat (permission denied, oversized) → hard `credential_file`. JSON must parse to a non-null, non-array object, else hard `credential_json` (prototype `readCredentialJson`). `JSONPath` missing in a VALID object, or resolving to a non-string/empty value → `ErrNotFound` (this is what makes snake/camel and nested-or-flat tolerance declarative: Claude's `claudeAiOauth ?? oauth ?? flat` and Codex's `tokens.access_token ?? tokens.accessToken` become ordered AuthFile entries with different JSONPaths — decision D4). Extracted token failing `security.ValidateOpaqueToken` → hard `unsafe_credential`. `ExtraPaths` values are extracted the same way into `Credential.Extra` (missing = omitted). `ExpiryPath`, when set: extracted value run through `ParseExpiry`; past → hard `expired_credential`; unparseable → hard `expired_credential` (prototype fail-safe: `!isFinite(ms) || ms <= now`, `usage-allowance-checks-spec.md` §2.1). Success → `Credential{Token, Extra, Source: AuthFile, Mode}` (Mode = file POSIX mode from `ReadBoundedFile`).
4. **Permission warnings.** When the winning file's mode has group/other bits set (`security.HasBroadPermissions`), FileResolver records a warning `"credential file <path> has broad permissions (<mode>); review before continuing"` (prototype's Claude warning generalized, `usage-allowance-checks-spec.md` §2.1). Exposed via `FileResolver.Warnings()` after a Resolve; aggregated by `ResolveChain`. **Never** chmod or otherwise remediate (global SPEC §6 invariant 6).
5. **CLIResolver.** Runs `Command` with `Args` via `os/exec.CommandContext` under a hard deadline (min of `ctx` deadline and `Timeout`). Output is capped at `MaxCLIOutputBytes` (default `MaxCLIOutputBytes = 32 * 1024`, prototype `maxBuffer: 32_768`). Strips exactly one trailing `\r\n` or `\n` from stdout (prototype `tokenCandidate`, `usage-allowance-checks-spec.md` §2.3). **Every** failure — non-zero exit, timeout, output over cap, empty output, shape-invalid output — maps to `ErrNotFound` (candidate unavailable; annex-a §4 "every shell-out AuthSource MUST degrade to 'candidate unavailable,' never a hard error"; Copilot chain skips malformed tokens, §2.3). Success → `Credential{Token, Source: AuthCLIShellOut}`.
6. **Credential input channel (decision D1).** Credential material is NEVER passed to a subprocess via argv or environment: argv is visible to `ps`, env to `/proc/<pid>/environ` and child processes. When a future subprocess needs a secret as input (e.g. RPC init, F16), it is written to the subprocess's **stdin**. F12's CLIResolver only runs commands that emit the credential on stdout and never injects secrets itself.
7. **KeychainResolver.** `KeychainStore` interface (`Get(service, account) (string, error)`) decouples the resolver from the OS; `ManagedKeychainStore` adds `Set` and `Delete` for which-model-owned credentials. `DefaultKeychain()` returns the darwin implementation (`//go:build darwin && !nousage`) wrapping `github.com/zalando/go-keyring` (decision D2); on other platforms an `UnavailableKeychain` whose operations return `ErrNotFound` (annex-a §4: zed's keychain source is a no-op outside macOS). Resolver not-found → `ErrNotFound`; any other store error → hard `keychain_unavailable` with a sanitised message that cannot contain credential material.
7a. **ManagedStore.** Credentials completed by `auth login` use keychain service `"which-model"` and account `<provider>` when `UseKeychain` is true. Any unavailable/failed keychain write falls back to `<StateDir>/credentials/<provider>.json`, written through `config.AtomicWriteFile` with mode 0600; `UseKeychain = false` goes directly to that file. Resolution prefers the enabled keychain and falls back to the file; it returns `Source: AuthOAuthDeviceFlow`. `Remove` always attempts both locations, regardless of the current preference, and returns `ErrNotFound` only when neither existed. Provider IDs are validated before path construction. No error or warning includes token material.
8. **CookieResolver (interface only).** F12 exports the `CookieResolver` interface; browser-cookie extraction is **deferred to M5** (decision D3) using `github.com/browserutils/kooky` per annex-a §4. `ResolveChain` treats `AuthBrowserCookie` sources as candidate-unavailable (`ErrNotFound`).
9. **OAuthDeviceFlow.** Generic device-code state machine (`docs/plan/annex-a-provider-matrix.md` §3.3, `usage-allowance-checks-spec.md` §2.3/§4): `NewDeviceFlow(spec usage.OAuthSpec)`; `Start(ctx)` POSTs `spec.DeviceCodeURL` (form `client_id`+`scope`) and validates every response field — `device_code` opaque-valid, `user_code` matches `^[A-Z0-9-]{4,32}$`, `verification_uri` EXACTLY equals `spec.VerificationURI` (required; exact-match allow-list generalized from Copilot's fixed value), `expires_in` in [1,1800]s, `interval` in [1,30]s (default 5) — any violation → `unsupported_response` (decision D6). `Poll(ctx, code)` implements the prototype polling loop: local deadline from `expires_in`, deadline checked **before and after** each sleep (zero polls after deadline), `slow_down` → interval += 5 (cumulative), `authorization_pending` → retry, `access_denied` → `access_denied`, `expired_token` or deadline → `device_expired`, unknown error field → `unsupported_response`. Success returns the validated opaque token. The flow itself never persists credentials; F25 hands the result to `ManagedStore`. Only validated `UserCode`/`VerificationURI` are ever shown (global SPEC §6 invariant 9 / §2.3). `Now`/`Sleep` are injectable test seams (prototype clock injection).
10. **Transport (decision D7).** The device flow uses stdlib `net/http` plus F05 helpers — `security.ValidateExactHTTPS(url, []string{url})` for the two configured endpoints (self-allow-list: scheme/userinfo/hash checks; providers pin the real URLs), a `CheckRedirect` that hard-fails any 3xx (`redirect_refused`), and `security.ReadResponseBounded(resp, security.MaxResponseBytes)` for bodies. F12's dependency set is F05+F11 (graph §2), so `httpkit` (F04) is NOT imported here; the richer client is used by F14. The token-exchange POST is hand-rolled form encoding (no `golang.org/x/oauth2`; decision D8).
11. **Resolution.** `ResolveChain(ctx, sources, client)` walks declared `sources` in order: for each source it constructs the matching resolver, resolves a candidate, and runs `Validate` when present — validation failure skips the candidate. First accepted candidate wins; hard resolver errors abort; exhaustion returns `ErrNotFound`. `ResolveProvider` first calls `ResolveChain`; only after exhaustion, and only when the descriptor contains `AuthOAuthDeviceFlow`, it resolves `ManagedStore`, runs that OAuth source's `Validate`, and returns the managed candidate. This preserves env/file/CLI/provider-keychain precedence while making completed device logins usable by auth status, usage, and pick. `AuthOAuthDeviceFlow` in a bare chain remains non-interactive and candidate-unavailable.
12. **Expiry helpers.** `ParseExpiry(v any) (time.Time, error)`: JSON number → seconds-vs-milliseconds heuristic (`> 10_000_000_000` = ms, prototype `resetText`, `usage-allowance-checks-spec.md` §1); string → RFC3339/RFC3339Nano or numeric string; anything else → error. `CheckExpired(exp, now) error`: `now.After(exp)` → `expired_credential` FailureError, else nil.
13. **Build tags.** Every file in `internal/usage/credential/` carries `//go:build !nousage` (annex-a §1a.2). F21 provides the package-presence stub under `nousage`.

## Error behaviour

All hard errors are `*usage.FailureError` with canonical codes: `credential_file`, `credential_json`, `unsafe_credential`, `expired_credential`, `keychain_unavailable`, `redirect_refused`, `unsupported_response`, `access_denied`, `device_expired`, `timeout` (device-flow request deadline), `provider_status` (non-2xx device endpoints), `network` (transport). `ErrNotFound` is a plain sentinel (never a FailureError). Messages are sanitised; every resolver carries a canary-token test proving its error paths never leak the token (global SPEC §6 invariant 5).

## Decisions

| # | Decision | Value | Rationale |
|---|---|---|---|
| D1 | CLI credential channel | **stdin** (never argv/env) | argv visible in `ps`, env visible via `/proc` and inherited by children; stdin is process-private. Assignment: "decide: env or stdin, record it". |
| D2 | Keychain library | `github.com/zalando/go-keyring` (darwin, build-tagged) | Annex-a §4 verified the module against pkg.go.dev (HTTP 200, 2026-08-07). Assignment acceptance: "verify plausible, record". Internet passwords (`github.com/keybase/go-keychain`) deferred to the zed provider. |
| D3 | Cookie extraction | deferred to M5; F12 exports only the interface | Assignment: "state explicitly". Annex-a §4 names `browserutils/kooky`; M5 owns the implementation and the `--allow-browser-cookies` opt-in. Stated explicitly: **F12 performs no browser access**. |
| D4 | Missing JSONPath in valid JSON | candidate unavailable (`ErrNotFound`), chain continues | Enables snake/camel + nested-or-flat tolerance as ordered AuthFile entries (Claude §2.1, Codex §2.2). Malformed JSON stays a hard `credential_json`. |
| D5 | Env/CLI candidate quality | empty/unsafe env values and ALL CLI failures → `ErrNotFound` | "Candidate unavailable, never a hard error" (annex-a §4); a bad env var or missing CLI must not block the file/keychain fallback. |
| D6 | Device-flow malformed responses | mapped to `unsupported_response` | Prototype's `device_response` code is not in the canonical `Failure.Code` table (global CONTRACTS §1.6); `unsupported_response` ("JSON parsed but wrong shape") covers it exactly. No new code added. |
| D7 | Device-flow transport | stdlib `net/http` + F05 security helpers | F12's dependency set is F05+F11 (graph §2) — `httpkit` is not importable here. Redirect rejection + body bounding are each ~10 lines via F05 helpers. |
| D8 | Token exchange | hand-rolled form POST (stdlib) | Full control of redirect rejection and error mapping for a single form-encoded POST; `x/oauth2` adds nothing until the refresh-grant kind lands (F15). |
| D9 | `OAuthSpec.VerificationURI` required | exact-match against server value | Security invariant 1 (exact allow-lists): a compromised device endpoint must not steer the user to a phishing URL. |
| D10 | Credential type | re-export `type Credential = usage.Credential` (F11) | F11 owns the type (annex-a §5) to avoid an import cycle; F12's alias keeps resolver signatures readable. |
| D11 | Chain hard-error policy | resolver hard errors abort the chain; Validate failures skip | Matches prototype: Claude/Codex file errors are fatal (`§2.1`/`§2.2`), Copilot's per-source validation skips (`§2.3`); annex-a §5 "candidate that fails Validate is skipped, not fatal". |
| D12 | Non-darwin keychain | `ErrNotFound` (no-op) | Annex-a §4: keychain sources are macOS-specific; a missing capability degrades to "no candidate", never a crash. |
| D13 | Managed sign-in storage | OS keychain by default; private state-file fallback when unavailable or explicitly disabled | Protect credentials on supported hosts without making login unusable in headless/non-keychain environments; removal always clears both stores. |

## Out of scope

- Browser-cookie extraction implementation (M5, `browserutils/kooky`), incl. the `--allow-browser-cookies` opt-in.
- Keychain internet-password retrieval (`keybase/go-keychain`, zed provider).
- OAuth refresh-grant resolver, AWS SigV4, Volcengine AK/SK, subprocess JSON-RPC, and Connect-RPC/gRPC-Web token resolvers (F15–F17 implement these kinds).
- Identity-gate endpoints (Copilot `GET /user`), device-flow display wiring, `--login`, unattended-refusal — F17/F25.
- `nousage` stub file for this package — F21.

## Review corrections (#176, #177)

File candidates expand a leading `~/` using `os.UserHomeDir` and `$NAME` or `${NAME}` using `os.LookupEnv`, without invoking a shell. Missing or empty referenced variables make that candidate unavailable; they must never produce `/auth.json`. Expansion is single-pass: environment values are literal paths, with no recursive expansion or command substitution. Absolute and ordinary relative paths retain their meaning. Resolve candidates in declared order and keep existing bounded reads, validation, expiry, and permission warnings. This clarifies the descriptor paths already declared by F15/F16.

Keychain absence includes both the keyring not-found sentinel and `credential.ErrNotFound`, including wrapped errors. Both continue resolution as required by D12. Locked, denied, and unexpected errors remain sanitized `keychain_unavailable` failures.
