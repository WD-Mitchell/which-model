# F01 — config: SPEC

## Purpose

`internal/config` owns the configuration surface of the `which-model` binary: the TOML config files, their discovery and precedence order, the `WHICH_MODEL_` environment overrides, the `[usage] enabled` three-state and the `[providers.<id>]` tables, data-directory resolution, and validation. It is deliberately **generic**: F01 types only `[usage]` and `[providers.<id>]` (which M1/M2 core features need at load time); every other section (`[bands]`, `[strategy]`, `[scoring]`, `[catalog]`, `[catalog.publish]`, `[output]`) is decoded on demand by the feature that owns its semantics through the single accessor `UnmarshalKey`. F01 is Layer 0: it imports no `internal/` package (dependency rule, `specs/global/CONTRACTS.md` §8; F01 has `depends_on: —` in `specs/DEPENDENCY-GRAPH.md` §2 and blocks F19, F21, F22, F30).

Source: `docs/plan/annex-d-cli-reference.md` §1.1a (env prefix), §1.2 (`--config`), §3.4/§4.1/§4.2/§4.4/§4.5 (resolution order, annotated config, env mapping, XDG/macOS paths); `docs/plan/README.md` §6 (usage toggle, provider default-deny); `specs/global/CONTRACTS.md` §5.1 (UsageEnabled), §8 (import boundaries); `specs/global/SPEC.md` §5 (exit codes).

## Behaviour

1. **Config file names are fixed.** Project config: `./.which-model/config.toml` relative to CWD, searched upward (see B4). User config: `$XDG_CONFIG_HOME/which-model/config.toml` (default `~/.config/which-model/config.toml`) on non-darwin; `~/Library/Application Support/which-model/config.toml` on darwin (annex-d §4.1 item 3-4, §4.5). `~/.wdm/` MUST NOT be used for anything (annex-d §4.5).
2. **Resolution order (highest to lowest):** (1) explicit `--config <path>` flag value; (2) `$WHICH_MODEL_CONFIG` env var naming a config file; (3) project config (first found walking upward); (4) user config; (5) built-in defaults. An explicitly named file (flag or env) **bypasses** project/user discovery; missing explicit file is a hard error. The merged result is then overlaid by `WHICH_MODEL_` key overrides (B8) and validated. `which-model config show` prints the result after this full merge (annex-d §4.1; the `_sources` map itself is F22-cli-skeleton's composition concern, see Out of scope).
3. **Merge semantics.** Loading starts from `Default()`; each file layer decodes into the existing value with BurntSushi/toml's merge-into-existing semantics: keys absent from a layer keep their current value, map sections (`providers`) merge per provider id and per key, slice values are replaced wholesale by the higher layer (annex-d §4.1 "first found wins; does not merge multiple project configs" applies to the project *walk*; the user+project layers both merge). Env overrides apply after all file layers.
4. **Project walk.** `ProjectConfigFile(cwd, home)` walks upward from `cwd`; at each directory it checks `dir/.which-model/config.toml` (first hit wins), then stops if `dir` contains `.git` (file or directory — the git root itself is checked), if `dir == home`, or at the filesystem root. If no git root exists, the walk is bounded by `$HOME` (exclusive). (annex-d §4.1 item 3, §4.5.)
5. **User data paths.** `ResolvePaths(goos, home, getenv)` returns user config file, config dir, cache dir, and state dir per annex-d §4.5: on `darwin`, `~/Library/Application Support/which-model/` (config; `state/` subdirectory), `~/Library/Caches/which-model/` — `XDG_*` env vars are ignored unconditionally on darwin; on other OSes, `$XDG_CONFIG_HOME`/`$XDG_CACHE_HOME`/`$XDG_STATE_HOME` with defaults `~/.config`/`~/.cache`/`~/.local/state`, each suffixed `/which-model/`.
6. **`[usage] enabled` three-state.** The TOML value is a boolean or the string `"auto"`; it decodes into the canonical `UsageEnabled` type (`specs/global/CONTRACTS.md` §5.1): `true` → `UsageTrue`, `false` → `UsageFalse`, `"auto"` → `UsageAuto`. Default `"auto"`. Any other value is a validation error. F01 only parses and validates the value; resolving it to an effective boolean (`auto` ↔ at least one `[providers.<id>].enabled = true`, L0/L1 refusal semantics, degraded mode) is F21-usage-toggle's concern (README §6, annex-d §3.4).
6a. **`[usage] backend` selection.** The TOML string is `"off"`, `"native"`, or `"codexbar"` and decodes into `config.UsageBackend`; the default is `"off"`. The selected backend is consumed by F21/F24 and does not change the `usage.enabled` three-state parser.
7. **`[providers.<id>]` and default-deny.** Each known provider id has an optional table with `enabled` (bool, default `false`), `priority` (int, default `0`), `weight` (decimal, default `1.0`), `cache_ttl` (duration string, default unset), `source_preference` (array of strings, default empty), `credential_path` (string, default `""`), `trusted_fallback_origin` (string, default `""`). Unlisted providers are absent from the map, which reads as disabled. **Default-deny:** a fresh install enables zero providers and reads no credential material until a provider is explicitly enabled (README §6.2, annex-d §4.2). A provider `weight` of `0` or absent is normalized to `1.0` (multiplicative identity in `FinalScore`); a negative weight is a validation error. (annex-d §4.2 `[providers.claude]` …; provider semantics beyond enablement — priority ordering, weight consumption — are F15-F17/F19/F20 concerns.)
8. **Env overrides.** Prefix `WHICH_MODEL_` (annex-d §1.1a: `WM_` collides with X11 tooling). Dotted config keys map to env names by uppercasing and replacing `.` with `_` (e.g. `usage.enabled` → `WHICH_MODEL_USAGE_ENABLED`, `providers.claude.enabled` → `WHICH_MODEL_PROVIDERS_CLAUDE_ENABLED`; provider ids are kebab-case, `-` → `_` in env names — annex-d §4.4). F01 ships a **closed env-key vocabulary**: every env-addressable scalar key from the annotated config (annex-d §4.2) — `usage.enabled`; `strategy.{default,default_profile,tier1_share,tier2_share}`; `bands.{direction,gate_above_used_percent}`; `scoring.{normalizer,aggregator}`; `catalog.{raw_csv_path,scores_csv_path,provider_config_path,benchmark_config_path,cache_ttl,warn_on_stale_scores}`; `catalog.publish.{enabled,schedule,timezone,mode,auto_merge,merge_method,commit_message,pr_title,run_tests}`; `output.{color,timestamps,identity_default}`; `providers.<id>.{enabled,priority,weight,cache_ttl,credential_path,trusted_fallback_origin}` — with arrays excluded (`bands.tier`, `catalog.publish.{branches,pr_labels}`, `providers.<id>.source_preference`, annex-d §4.4). `ApplyEnv` resolves every `WHICH_MODEL_*` var (except `WHICH_MODEL_CONFIG`) against the vocabulary by longest-suffix key match, so the dotted key is known immediately: a var that matches no key is an error at ApplyEnv time (strict allow-list, annex-d §1.4). F01-typed keys set the typed fields eagerly; generic keys are stored as `dotted key → raw value` and applied by `UnmarshalKey` against the owning feature's struct (B10). `$WHICH_MODEL_CONFIG` is a path override consumed by `Load`, never a key override. Extending the config vocabulary (a new key) updates the vocabulary table and its tests (D14).
8a. **Backend environment override.** `WHICH_MODEL_USAGE_BACKEND` sets `usage.backend` and accepts exactly `"off"`, `"native"`, or `"codexbar"`.
9. **Strict unknown keys.** A config file key that no owned section decodes is an error, not a warning: F01 rejects unknown keys under `usage.*` and `providers.<id>.*` eagerly at load; unknown keys under generic sections are rejected by `UnmarshalKey` at first decode of that section. Unknown `WHICH_MODEL_*` vars are rejected eagerly by `ApplyEnv` against the closed vocabulary (B8). (Strict allow-list posture, annex-d §1.4.)
10. **`UnmarshalKey(key, out)`.** Decodes the merged TOML subtree at the dotted `key` into `out` (any pointer to a struct; callers pre-populate their own defaults — decode is merge-into-existing), then applies any stored `WHICH_MODEL_*` override for fields of that subtree even when no config file declares the table (matched by toml tags; scalar kinds only: string, bool, int, `time.Duration`, anything implementing `encoding.TextUnmarshaler`, or a pointer to any of these — a nil pointer is allocated so callers keep unset-vs-zero semantics), then rejects unknown keys inside the subtree. A missing TOML key with no matching environment override leaves `out` untouched and returns nil. A present key must address a TOML table. This is the only F01 mechanism by which other features read config (DECISION B: `[bands]` → F19, `[strategy]` → F20, `[scoring]` → F09, `[catalog]` → F23, `[catalog.publish]` → F30, `[output]` → F22).
11. **Validation.** `Validate` checks the F01-owned surface: `usage.enabled` is one of the three canonical values, every provider id is non-empty, every provider weight is `>= 0` (zero normalized to `1.0`), every provider `cache_ttl` is `>= 0`. Section-specific semantics (band tier ordering, publish mode/branches, strategy names, normalizer/aggregator names, provider registry ids) are validated by the owning features at their `UnmarshalKey` call. (annex-d §4.2/§4.3; README §6.1.)
11a. **Backend validation.** `Validate` rejects any programmatically constructed `usage.backend` outside `{off,native,codexbar}` with key `usage.backend`.
12. **Decimal config values.** `providers.<id>.weight` is `decimal.Decimal` (shopspring). TOML floats reach it through BurntSushi/toml's `TextUnmarshaler` path (`fmt.Sprintf("%f", …)` → `UnmarshalText`), which preserves literals exactly up to 6 fractional digits — the canonical tables use ≤ 2 — and truncates beyond that (documented decoder behavior; see D12). No `float64` field exists anywhere in the numeric config surface (annex-b §1 no-float64 rule).
13. **Resolved-config rendering.** `MarshalTOML` renders the fully resolved configuration for `config show` (annex-d §2.7): `[usage]` and `[providers.<id>]` from the typed values (env applied, weights normalized), generic sections from the merged file document, and every stored env override merged into its section (dotted keys, B8). Rendering rules: `UsageAuto` → `"auto"`, `UsageTrue`/`UsageFalse` → TOML booleans; decimals and durations render as TOML strings (`weight = "0.85"`, `cache_ttl = "1h"` — they decode back through the same `TextUnmarshaler`/`time.ParseDuration` paths, so the render round-trips); env override values infer bool (`strconv.ParseBool`) → int (`strconv.Atoi`) → string. Section order is canonical: `usage`, `scoring`, `strategy`, `bands`, `catalog`, `output`, `providers` (annex-d §4.2 order), providers sorted by id; generic sections appear only when present in a file layer or via env (F01 does not know their defaults — D16).
13a. **Backend rendering.** `MarshalTOML` always renders the resolved `usage.backend` string under `[usage]`.

## Error behaviour

- `ConfigError` is the single error type; `ExitCode()` returns **2** for every kind ("Argument/config error", `specs/global/SPEC.md` §5; config failures are deterministic and retry-identical, annex-d §3.4). The CLI layer (F22) maps any `*config.ConfigError` to exit 2; other errors (I/O plumbing that is not config-shaped) are surfaced by callers as runtime errors.
- `KindNotFound` — an explicitly requested config file (`--config` value or `$WHICH_MODEL_CONFIG`) does not exist. Discovered files that are absent are NOT errors (defaults apply).
- `KindUnreadable` — a discovered or explicit file exists but cannot be read (permissions, directory-in-path, etc.).
- `KindInvalidTOML` — the file's TOML does not parse.
- `KindInvalidValue` — a value fails validation: unknown key in a decoded section, `[usage] enabled` not one of the three states, provider weight negative, `cache_ttl` not a parseable duration or negative, env override not parseable for its target type, unknown `WHICH_MODEL_*` var in an owned namespace, `UnmarshalKey` key not a table, unknown key inside a decoded subtree.
- Distinction guaranteed by the kind taxonomy: **missing file** (`KindNotFound`) vs **malformed file** (`KindInvalidTOML`/`KindInvalidValue`) are always distinguishable via `errors.As` + `Kind`.
- Error messages name the file (`Path`) and the dotted key (`Key`) where applicable; they never contain credential material (there is none in config values F01 reads).

## Out of scope

- Cobra command tree, `--config` flag declaration, exit-code mapping, `config show|set|path|validate` commands, `_sources` reporting → F22-cli-skeleton (F01 exposes the layer primitives: `Load`, `LoadFile`, `ProjectConfigFile`, `ResolvePaths`, `Validate`).
- `[usage] enabled` resolution (auto ↔ ≥1 enabled provider, `--no-usage` interplay, degraded mode, `usage_disabled`/`usage_compiled_out` codes) → F21-usage-toggle.
- Section schemas and defaults: `[bands]` → F19, `[strategy]` → F20, `[scoring]` → F09, `[catalog]` → F23, `[catalog.publish]` → F30, `[output]` → F22. F01 ships defaults only for `[usage]` and providers.
- Provider identity/registry knowledge (which ids exist, priority semantics, source-preference meaning) → F15-F17 (Annex A registry).
- `nousage` build tag and its stubs → F21; F01 compiles identically under both variants (it never touches `internal/usage`).
- The `providers.toml`/`benchmarks.toml` catalog data files → F23/F30 (their `provider_config_path`/`benchmark_config_path` keys are read via `UnmarshalKey("catalog", …)`).
